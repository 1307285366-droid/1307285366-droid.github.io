# 狂k重点 · 纯静态刷题网站

一个**不用框架、不用构建、不用 npm 依赖**的在线刷题网站。双击 `index.html` 就能跑，
所有判分和进度都在浏览器本地完成。

站点名字叫 **狂k重点**，打开后先看到的是封面：封面上列出题库，点开某个题库才看到它的章节，
再点章节才进答题。另外还有两个独立页面：**错题本**（按题型细分，可以直接在里面重练）和
**我的**（累计数据、收藏、错题入口、清空数据）。

题库来自考核附件 `题库/Web题库.md` 与 `题库/Java题库.md`，
并把附件 `原型/index.html` 里的示例数据也一并收进了 `原型示例题库`。

---

## 1. 设计思路

### 1.1 先想清楚“一份数据只描述一次”

刷题站最容易写歪的地方是：题干在一处、选项在另一处、答案在第三处，判分公式又在第四个地方。
改一道题要翻四个文件，改完还容易不一致。所以这个项目坚持两条：

- **题库只有一份**：`data/banks.js`（由 `tools/convert.mjs` 从 Markdown 生成），
  是唯一的事实来源；收藏、进度、成绩都只引用题目的 `id`，不复制题干。
- **判分只有一个函数**：`assets/js/quiz.js` 里的 `Quiz.submit()`。
  答题页、结果页、错题清单都调用同一套 `Quiz.stats()` / `Quiz.submit()`，
  不存在“练习时算一种、交卷时又算一种”的可能。

### 1.2 分层：能在手机上跑，也要能看懂

```
index.html                 页面骨架（只负责挂载）
assets/css/app.css         淡粉色主题
assets/js/util.js          转义、代码块渲染、计时格式化
assets/js/auth.js          手机号注册 / 登录（纯本地演示）
assets/js/storage.js       按身份分开的 localStorage 读写
assets/js/quiz.js          组卷 / 判分 / 统计 / 错题本（核心，纯逻辑）
assets/js/support.js       智能客服知识库（关键词匹配，不联网）
assets/js/ui.js            视图，只把状态渲染成 HTML
assets/js/app.js           状态、路由、事件、计时、账号、分享
data/banks.js              生成出的题库数据
data/raw/Web题库.md        原始 Markdown（只读留档）
data/raw/Java题库.md       原始 Markdown（只读留档）
data/raw/原型示例.md       附件原型里的示例数据，同一套格式
data/raw/参考原型.html     附件原型的原文件留档（不改动）
tools/convert.mjs          Markdown -> data/banks.js
tools/smoke-test.mjs       Node 冒烟测试（数据 / 幂等 / 账号 / 客服）
tools/render-test.mjs      Node 渲染/交互测试（极简 DOM 桩）
```

`quiz.js` 不碰 DOM，`ui.js` 不改状态，`app.js` 只做粘合。
想改判分规则只动 `quiz.js`，想改样式只动 `app.css`，不需要来回翻。

### 1.3 Markdown 转换（这是本题要求的工作，不是可选项）

`tools/convert.mjs` 把 Markdown 解析成结构化数据。Markdown 并不规整，脚本专门处理了：

- 章节标题（`## 一、HTML基础`）、题目标题（`### 12. 多选题`）→ 章节 / 题型；
- 选项之间的代码块（` ```java `）**不会被误当成选项行**；
- 解析里的 Markdown 链接、行内 `<code>`、多行解析都原样保留为文本，前端再安全渲染；
- 题干里的原始 HTML（如 `<a href="...">`）在页面里被**转义成纯文本**，不会真的执行。

转换脚本坚持“**只转换，不修改**”：题干、选项、答案、解析一个字都不动。

### 1.4 附件里还有一份没被用上的内容：`原型/index.html`

考核附件除了 `题目.md` 和 `题库/`，还有一个 `原型/index.html`——一份只实现了基础功能、
用示例数据（`JavaScript 基础` 4 题、`网络基础` 3 题）的参考原型。

我把这份原型也接进了站里，做法是**不另起一套数据格式**：把它的示例题按与正式题库完全相同的
Markdown 格式写进 `data/raw/原型示例.md`，由同一个 `tools/convert.mjs` 一起生成。
首页因此有三个题库，其中“原型示例题库”在标题里就写明了是示例数据，不会和正式题库混淆。
原型原文件也原样留档在 `data/raw/参考原型.html`，方便对照它原本长什么样。

对照原型，站里保留了它的界面骨架（顶部进度条、题库列表、题目卡片、选项状态、结果页四宫格），
但把蓝色主题换成了题目要求的淡粉色，并补齐了原型没有的持久化、收藏、错题、分享、计时。

### 1.5 怎么处理原题库里的脏数据

原题库不保证规范，实际发现了 5 处问题。**我没有改题目，而是标注出来、从计分里剔除**：

| 题目 | 问题 | 处理 |
|---|---|---|
| Web 第 31 题 | 只有答案和解析，没有选项 | 标记 `invalid`，不计分 |
| Web 第 80 题 | 答案标为 `E`，但选项只有 A–D | 标记 `invalid`，不计分 |
| Java 第 71 题 | 缺少“答案”字段 | 标记 `invalid`，不计分 |
| Java 第 108 题 | 答案标为 `A`，解析结论却是 `D` | 标记 `invalid`，不计分 |
| Java 第 174 题 | 答案标为 `A`，解析结论却是 `D` | 标记 `invalid`，不计分 |

这些题仍然会出现在答题流程里（能读到题干和解析），但会显示“本题不计分”，
并且不计入正确率。这样既不违背“不修改题库内容”，也不会让同学因为题库自身的错误丢分。

### 1.6 信息架构：封面 → 题库 → 章节 → 答题

```
封面（狂k重点）                ← 默认打开的一屏
 ├─ 点「Web前端题库」→ 题库页：6 个章节的列表
 │    ├─ 点「一、HTML基础」→ 答题
 │    └─ 点「全部练习」    → 答题
 └─ 点「Java程序设计题库」→ 同上（1 个章节，219 题）

底部四个标签：题库 | 错题 | 收藏 | 我的
```

- **题库**（第一个标签）：大标题「狂k重点」+ 题库卡片（带进度条）+ 继续上次练习。
- **题库详情**：只列章节，不做题。每章显示题量、题型细分、已练进度。
- **错题本**（第二个标签）：做错的题自动收进来，**按单选 / 多选 / 判断分开**，可以只练某一类；
  可以在里面直接重练，**做对了就自动移出**，也可以手动“已掌握，移出”或清空。
- **收藏**（第三个标签）：按题库分组列出收藏题，可以整套重练、逐条取消。
- **我的**（第四个标签）：身份卡片 + 四项数据 + 六个入口：
  统计分析、测试记录、错题本、我的收藏、智能客服、设置。

几个子页面的内容：

- **统计分析**：总览（已练题 / 正确率 / 测试次数 / 累计用时）+ 按题库、按题型、按章节的正确率条。
- **测试记录**：每次交卷都会记一笔（题库、范围、正确率、用时、时间），最多存 100 条，可清空。
- **智能客服**：纯本地关键词匹配，预置 12 条常见问题，答不上来会直说“答不上来”，不胡编。
- **设置**：账号（登录 / 退出）、显示（计时开关、大字号模式）、数据（清空）、关于。

会话（session）里只存“题目 id 列表”，不绑定某一个题库，
所以错题本可以把 Web / Java / 原型 三个题库的错题混在一起练。

### 1.7 账号：游客 → 手机号注册

- **默认是游客**，不登录也能正常刷题、收藏、看错题，数据存在本机。
- 注册要填：11 位手机号 + 验证码 + 密码（≥ 6 位）+ 昵称（可选）。
- **验证码是演示的**：这是纯静态网站，没有后端发不了真短信，所以点「获取验证码」会把
  6 位数字直接显示在页面上（10 分钟有效），完整走一遍注册流程。
- **每个身份一份数据**：存储 key 是 `quizmvp.v1.guest` / `quizmvp.v1.u_138xxxxxxxx`，
  游客和各个账号互不干扰。
- **注册时会把游客已有的进度带过去**（收藏、错题、记录、设置），注册后不会“白干”。

> ❗安全声明：密码只在本地做了一次“避免明文”的哈希（`assets/js/auth.js` 里的 `hash()`），
> **不是密码学安全的做法**，任何能打开浏览器控制台的人都能改本机数据。
> 真实产品的账号必须由服务端接收密码、加盐慢哈希（bcrypt/argon2）后存库。
> 也请不要在这里使用你在其它网站的真实密码。

### 1.8 需求之外我补的东西（对应题面第四节）

| 场景 | 做法 |
|---|---|
| 熄灯宿舍躺着刷 | 整体淡粉低饱和度、无纯白刺眼背景；字号偏大、行高 1.7 |
| 地铁里单手扶栏杆 | 单列布局、按钮最小高度 44px、点击区域够大、底部固定导航 |
| 两百多题只想刷第一章 | 题库 → 章节，每章单独入口，不用先勾选再开始 |
| 做到第 80 题被叫走 | 每答一题就写入 `localStorage`，刷新/关掉重开自动恢复，题库页还有“继续上次练习” |
| 一题就想知道对不对 | **每题提交后立刻判分、立刻在题卡顶部把正确答案挑出来**，不用等到交卷 |
| 没做完就想看记录 | 每答一题就更新一次答题记录（标为「未完成」），不做完也不会白做 |
| 只想再看错的 | 单独的错题本页面，按题型细分；**只增不减**，确认掌握后手动「已掌握，移出」 |
| 做完想再刷一遍 | 题库页/我的页有「重刷做过的」，**新结果覆盖旧结果，但错题本不变** |
| 考前标记重点 | 每题右上角 ☆ 收藏，收藏页按题库分组，可整套重练 |
| 和室友比正确率 | 结果页“分享成绩”，手机上走系统分享，桌面上复制文案 |
| 交完想知道差在哪 | 结果页给出**简单分析**：按题型对错 + 薄弱章节 + 一句人话结论 |
| 手机字号小看不清 | 设置里可开「大字号模式」，可关掉答题计时 |
| 找不到人问 | 内置智能客服，12 条常见问题 + 关键词匹配 |
| 想看自己弱在哪 | 统计分析：按题库 / 按题型 / 按章节的正确率条 |
| 好看吗 | 淡粉 + 圆角卡片 + 柔和阴影；题目卡片、柔和渐变、分隔小点、选项三态颜色，不多不少 |
| 计时 | 答题页实时计时，结果页显示总用时 |

## 2. AI 使用情况

本项目全程使用考核指定的 `pi-agent` + `deepseek-flash` 辅助开发，我负责选题、定方向、验收。

### 2.1 AI 主要帮了什么

- 通读两份长 Markdown 题库（合计约 340 题），梳理出章节 / 题型 / 选项 / 答案的规律；
- 写出 `tools/convert.mjs` 解析器，并处理代码块、行内标签等边界；
- 搭出 `util / auth / storage / quiz / support / ui / app` 的分层骨架；
- 写 `tools/smoke-test.mjs`，把“重复提交成绩不变”写成可自动跑的断言；
- 生成淡粉色主题 CSS 初稿。

### 2.2 AI 给过错方案 / 走过的弯路（都是我发现的）

1. **环境判断错误**：AI 一开始想直接用 `bash` 工具跑命令，结果主会话里报
   “No bash shell found”。它没有停下来问，而是继续猜——后来才确认：这台机器的
   主会话没有可用 shell，但子线程可以拿到 `powershell`，且系统里装了 Node。
   教训：**环境问题要先验证，不要让 AI 反复猜**。
2. **写盘位置踩坑**：AI 以为项目要写在 `D:\考核`，但 `write` 工具对 D 盘一直返回
   `EPERM`。实测后发现是**工具层限制**，而 PowerShell 对 `D:\考核` 是可写的。
   最终方案：在 C 盘开发、用 shell 复制到 `D:\考核`。
3. **差点把脏数据“改了”**：AI 第一版解析器遇到 Web 第 80 题（答案 E、选项只有 A–D）
   时，倾向于“顺手把答案改成 B”。这违反“不修改题库内容”，被我否掉，
   改成 `invalid` 标注 + 不计分。
4. **差点相信答案标注**：Java 第 108、174 题答案写 A、解析却写 D。
   AI 一开始只按答案字段判分，导致“按解析选反而被判错”。发现后统一改为标注 + 剔除。

### 2.3 我怎么验证 AI 的产出

- `node tools/convert.mjs` 打印每个题库的题量与异常清单，和 Markdown 头部声明
  （Web 120 题、Java 219 题）逐项对得上；
- `node tools/check.mjs`（一键自检）：先确认「引用的文件都在」+「全站零外部依赖」，
  再依次跑下面两个测试脚本；
- `node tools/smoke-test.mjs`（**80 项**）断言：题量、题型统计、结构合法性、
  **“同一题连续提交 4 次（含正确答案、错误答案、空答案），记录与统计完全不变”**、
  错题本的跨题库收集 / 按题型分组 / 排序 / 剔除异常题、交卷分析与测试记录口径、
  手机号校验与脱敏、验证码与密码校验、多身份数据隔离、旧数据自动补齐、客服匹配；
- `node tools/render-test.mjs`（**57 项**）用一个极简 DOM 桩在 Node 里真跑一遍 ui.js + app.js：
  题库 → 详情 → 章节 → **即时判分** → 幂等 → **未完成也记账** → 交卷 → **分析**
  → **重刷（错题本不变）** → 错题本 → 收藏页 → 我的 → 统计分析 → 测试记录
  → 智能客服 → 设置 → 注册 / 退出 / 登录；
- 浏览器里手动走完整流程（包括强刷、改窗口宽度到 375px 看布局、刷新恢复）。

## 3. 运行方式

### 最简单：双击打开

直接用浏览器（Chrome / Edge / Firefox 均可）打开项目根目录的 **`index.html`** 即可。
不需要安装任何依赖，不需要联网，不需要构建。

> 之所以能双击运行，是因为题库被打包成了 `data/banks.js`（`window.__BANKS__ = ...`），
> 而不是用 `fetch` 去读 `.md`／`.json`——`file://` 协议下 `fetch` 会被浏览器拦截。

### 可选：用静态服务器打开

如果习惯用服务器（Linux 验收环境同理）：

```bash
# 任选一种，在项目根目录执行
python3 -m http.server 8000
# 或
npx serve .
```

然后访问 `http://localhost:8000/`。

### 重新生成题库数据（可选，不是运行前提）

`data/banks.js` 已经生成好并随项目一起提交。若修改了 `data/raw/*.md`，可以重新生成：

```bash
node tools/convert.mjs     # Markdown -> data/banks.js（改了题库才需要跑）
node tools/check.mjs       # 一键自检：纯静态 + 数据 + 两个测试（推荐每次改完都跑）
```

`check.mjs` 会依次验证：

1. `index.html` 引用的每个文件都存在；
2. **全站没有任何外部 URL / `fetch` / `XMLHttpRequest` / 动态 `import`**——
   也就是能离线双击运行的硬保证；
3. 题库能加载、346 道题 id 全局唯一、异常题都有说明、有效题答案都在选项内；
4. 跑通冒烟测试与渲染/交互测试。

`node` 只在“重新生成 / 自检”时需要；**运行网站本身完全不需要 Node**。

## 4. 如果再给我 1 小时，最想完善什么？

**最想补：答题卡（题目导航网格）。**

理由：现在做到第 80 题被叫走，回来能恢复到第 80 题，但如果想回头改看第 12 题，
只能一路点“上一题”。两百多题的题库里，这个操作成本很高。
加一个可展开的答题卡（按题号显示“未答 / 已答对 / 已答错”，点号直达），
对“只想再看那几道错的”和“考前过一遍标记题”这两个场景的体验提升最直接。

其次想补：

- **把账号真正做成服务端**：现在验证码是假的、密码存在本机，只能算演示；
- 数据可视化：按章节画正确率曲线，一眼看出自己哪一章最弱；
- 选项乱序开关（防止靠位置背答案）；
- 更完整的无障碍（键盘 1–4 选项、`aria-*` 状态）。

## 附：开发与交付

开发在 `C:\Users\李珂\quiz-mvp`，交付目录是 `D:\考核`。两边靠两个脚本保持同步：

- `tools/sync.ps1`：用 `robocopy` 把项目同步到交付目录。**故意不带 `/MIR`**，
  所以只新增和覆盖，**绝不删除**交付目录里已有的东西。
- `tools/watch-sync.ps1`：每 2 秒扫一次项目文件，**一有改动就自动同步**，
  所以每次改完不需要手动再复制一遍。日志写在 `%USERPROFILE%\quiz-sync.log`。

手动同步一次、或者把它停掉：

```powershell
# 同步一次
powershell -ExecutionPolicy Bypass -File tools\sync.ps1

# 停掉后台的自动同步
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.CommandLine -like '*watch-sync.ps1*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

**答题**

- 题干、全部选项；单选 / 多选 / 判断三种题型
- **每提交一题就立刻判分**：题卡顶部直接出现一条答案条（对/错 + 正确答案 + 你选的），
  下面紧跟解析，**不用等交卷**
- 上一题 / 下一题 / 交卷；实时显示“第几题”“已答对”“已作答”“用时”
- 每题可收藏；重刷模式下题卡上有「重刷」标记

**结果**

- 正确率环、**对几道 / 错几道** / 未作答 / 无效题
- **简单分析**：一句结论 + 按题型的对错条 + 薄弱章节（错得最多的章节）
- 错题回顾（含解析）、只练本次错题、重刷本次（覆盖记录）、看错题本
- 分享成绩

**错题本（第二个标签）**

- 做错的题自动收进来（结构异常的题不收）
- **按单选 / 多选 / 判断三组分开**，每组可单独开练
- **只增不减**：在错题本里答对也不会自动消失，确认掌握了再点「已掌握，移出」；也可整本清空

**重刷做过的题**

- 入口在题库详情页和「我的」页，把做过的题再刷一遍
- **新结果直接覆盖旧结果**（已练记录、正确率、答题记录都更新）
- **但错题本一个字都不改**，避免重刷把错题“洗白”

**收藏（第三个标签）**

- 按题库分组列出收藏题，可整套重练、逐条取消

**我的（第四个标签）**

- 身份卡片：游客 / 已登录（昵称 + 脱敏手机号）
- 已练题 / 累计正确率 / 错题 / 收藏四项数据
- 六个入口：统计分析、测试记录、错题本、我的收藏、智能客服、设置

**统计分析**

- 总览：已练题 / 正确率 / 测试次数 / 累计用时
- 按题库、按题型、按章节的正确率条

**测试记录**

- **每答一题就记一笔**，没做完也算；交卷后同一条记录标记为「已交卷」
- 每条显示：题库范围、正确率、对 / 错 / 未答、用时、时间，重刷的记录带「重刷」标记
- 最多 100 条，可清空

**智能客服**

- 12 条预置常见问题 + 关键词匹配；认不出时明确告知，不胡编

**设置**

- 账号：登录 / 注册 / 退出；显示：计时开关、大字号模式；数据：清空；关于

**账号**

- 手机号 + 验证码 + 密码注册（验证码为本地演示）；未注册时以游客身份使用
- 每个身份一份独立数据，注册时把游客进度带过去

**通用**

- 刷新 / 关闭页面后自动恢复进度（localStorage）
- 淡粉色主题，移动端单列布局，底部四个标签：题库 / 错题 / 收藏 / 我的

## 附：判分、记录、重刷的规则

### 1. 每题即时判分，但同一题只认第一次提交

```js
// assets/js/quiz.js —— 幂等的关键
function submit(session, qid, picked) {
  const existing = session.answers[qid];
  if (existing && existing.submitted) return existing; // 重复提交直接忽略
  ...
}
```

双击“提交”也好、连点五次也好，**答案记录、正确率、错题次数都不会变**；
UI 层同时会把选项 `disabled` 锁住。

### 2. 一提交就出答案

提交后题卡**顶部立刻出现一条答案条**（✔/✘ + 正确答案 + 你选的），下面是解析。
不用等交卷，也不用往下翻。

### 3. 没做完也算进记录

| 记什么 | 什么时候写 |
|---|---|
| 错题本 | 每提交一题，做错就写 |
| 已练记录（正确率的分母） | 每提交一题，写最后一题的结果 |
| 答题记录（测试记录） | 每提交一题就新增/更新一条，`finished: false`；交卷时改成 `true` |

所以做到一半直接关页面，进度和记录也不会丢。

### 4. 重刷：覆盖记录，不动错题本

- **普通练习**：做错 → 进错题本（`times + 1`）；做对 → 也不自动移出错题本。
- **重刷（`mode === 'redo'`）**：新结果覆盖 `done[qid]`、更新答题记录，
  **完全不碰错题本**。
- 错题本只能通过两种方式变化：手动「已掌握，移出」、或「清空」。

> 为什么要这样：错题本是“我曾经错在哪”的账本，不应该因为重刷一次就被洗白；
> 而正确率是“我现在掌握得怎么样”，应该被最新的结果覆盖。两者分开，才说得清。
